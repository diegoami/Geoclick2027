# v0.8.0 — Something to hang a name on (planned 2026-09-19)

The programme that follows [PLAN_V0.7.md](PLAN_V0.7.md), which closed with
v0.7.0. That release added maps; this one is about what happens on the
first day with one. Geoclick can already tell you **that** you were wrong
and **where** the right answer was. It cannot tell you **why** a place is
where it is — and a name with nothing attached to it is a name you
re-learn every session, which is exactly what the ladder and the scheduler
are fighting against.

**Status: planned.** The product decisions below were taken by the product
owner on 2026-09-19; no task is started.

Input: the product owner's request — _"When I am on a new map I have no
clue how to start learning regions and cities. I start clicking around, the
name is shown but it does not stick. I know I remember the names of regions
because I know a fact about them that may be connected to its location,
such as there are elephants in Yunnan, pandas in Sichuan, Xinjiang is a
Muslim country… And a second feature: the overview maps may be too
political, and we might think of a way to show non-invasively elevation,
coast, rivers or anything that could help mnemonics."_ — and the counts
measured from the repo and from `data/source/` on the same day, recorded
under "What the source data holds" below.

The two features share one source of data, which is why they are one
programme: the thing that makes the map physical (Natural Earth's named
mountain ranges, deserts, basins and seas) is also the thing that makes a
derived fact worth reading.

## Where the facts live

Two files, because they have two different jobs. This is the same split the
repo already uses for maps: `data/source/` (input, gitignored) →
`data/maps/<id>/` (built, committed).

**Authored, by hand — `data/facts/<country>.json`.** One per country,
committed, the only file a person ever edits:

```
data/facts/china.json   data/facts/italy.json   data/facts/usa.json
```

```json
{
	"yunnan": {
		"wikidataid": "Q43194",
		"hook": {
			"en": "China's wild elephants live here and nowhere else — the tropical south, on the Laos border."
		}
	}
}
```

**Built, by script — `data/maps/<mapId>/facts.json`.** One per map,
generated by `build-facts.ts`, committed exactly as `map.json` and
`tour.json` already are, and sitting beside them:

```
data/maps/china-regions/
  map.json   tour.json   tiles.pmtiles     (exist today)
  facts.json                               (new)
```

It holds the derived fields for every target on that map, plus whichever
authored hooks apply to it.

**Why not one file.** A place belongs to several maps: Italy's provinces to
_Provinces_, _North_, _Center_ and _South_; US cities to _Cities_, _East_,
_Center_ and _West_. Authoring per country writes each sentence once and the
build projects it into every map that contains that place.

**No build plumbing is needed.** Checked, not assumed: `app/static/maps` is
a symlink to `data/maps`, and Vite copies each map folder into
`app/build/maps/<id>/` and on into the Android assets — so a `facts.json`
in that folder ships on web, desktop and Android untouched, fetched from
`/maps/<id>/facts.json` the way `tour.json` is today.

## What the source data holds

Measured 2026-09-19 from the committed maps and from `data/source/`.

**How much there is to say something about**

| Rows  | Unique country+name | Provinces | Cities | States | Regions | Counties |
| ----- | ------------------- | --------- | ------ | ------ | ------- | -------- |
| 2 235 | 1 817               | 668       | 1 182  | 205    | 159     | 21       |

Authoring a hook for every one of those is not a release. Authoring 103 is,
and the derived line covers the other 2 132 rows on day one.

**What the sources already carry, and did not have to be fetched**

- `ne_10m_populated_places`: `POP_MAX`, `POP1950`…`POP2025`, `ADM0CAP`
  (national capital), `CAPALT`, `ADM1NAME` (its region), `TIMEZONE`,
  `MEGACITY`, `WORLDCITY`.
- `ne_10m_admin_1_states_provinces`: `type_en`, `name_local`, `region`,
  `wikipedia`, `area_sqkm`.
- **A Wikidata id on nearly everything** — 4 332 / 4 596 admin-1 rows
  (94 %) and 7 192 / 7 342 populated places (98 %). Not used for content in
  this release, but it is the precise key that makes a later enrichment
  pass — or a correction — possible without fuzzy name matching.

**The five new physical datasets** (HTTP HEAD against
`naturalearth.s3.amazonaws.com/10m_physical/`, all present, all public
domain, all cached in the gitignored `data/source/`):

| Dataset                                     | Zipped |
| ------------------------------------------- | ------ |
| `ne_10m_ocean`                              | 3.0 MB |
| `ne_10m_rivers_lake_centerlines`            | 2.0 MB |
| `ne_10m_geography_regions_polys`            | 1.9 MB |
| `ne_10m_geography_marine_polys`             | 0.9 MB |
| `ne_10m_geography_regions_elevation_points` | 0.2 MB |

**The budget they have to fit in:** map data is 20 MB today and the Android
APK 29.7 MB — and `geoclickMap.ts` loads each tileset **whole into memory**
on desktop and Android, because neither shell serves range requests. The
physical layers are not free, which is what FT-33's size gate is for.

## Tasks

One branch per task, `feat/ft-NN-…`; `npm run gates` before pushing; verify
in a real browser with screenshots; **ask the product owner before every
merge**; tick the ledger after each merge. Same rules as the previous three
programmes. 🧑 marks a point where the task stops for the product owner.

Building maps needs the WSL2 toolchain (`ogr2ogr`, `tippecanoe`, `pmtiles`)
as MAPS.md's Pipeline section describes, and every changed build command
goes into MAPS.md as it lands.

### FT-33 — The map gets water and terrain · High

- **Why:** the Overview is politics only — flat coloured shapes on sand,
  with the sea the same colour as the land, so no coastline reads at all. A
  region needs something to sit _against_ before it can be remembered: the
  top of the boot, the one on the Black Sea, the one behind the Alps.
- **Do:**
  - five `fetch` lines in `data/scripts/fetch-natural-earth.sh`, same
    pattern as the existing three;
  - `selectSea`, `selectRivers`, `selectTerrain`, `selectMarine` in
    `data/scripts/mapBuildUtils.ts` — each a near-clone of the existing
    `selectNearbyLakes` (bbox `-spat` clip plus `-select`);
  - the same four `-L` layers on the `tippecanoe` call in **both**
    `build-map.ts` and `build-points-map.ts`, beside `lakes` and `context`;
  - four style layers in `data/styles/base.json` below `context-fill`, all
    `"visibility": "none"` by default: `sea-fill`, `rivers-line` (width
    from `scalerank`, so only the big rivers show when zoomed out),
    `terrain-fill` (a barely-there warm tint), and named terrain/marine
    labels;
  - **the labels are DOM popups through `labelCollision.ts`'s
    `registerLabel` at a low priority, not a MapLibre symbol layer** — the
    style's glyph URL points at a public font server and the desktop and
    Android builds must work with no network at all. Same rule as every
    other name in the app;
  - a **Terrain** toggle in `MapNav.svelte` beside the language pills,
    persisted through a new pref in `mapPrefs.svelte.ts` (the localStorage
    pattern favourites and recents already use). **Off by default** —
    "non-invasively", as asked;
  - rebuild all 63 tilesets.
- **The size gate:** if a map's `tiles.pmtiles` grows by more than **40 % or
  250 KB**, drop `terrain` and `marine` for that map and record the
  exception in MAPS.md. Report the before/after table for all 63.
- **Tests:** a unit test per selector; `map.json` and `tour.json` must come
  back **byte-identical** for a rebuilt map (only the tiles may change) —
  the established proof that a pipeline change altered nothing it should
  not have.
- **DoD:** gates green; MAPS.md updated with the new datasets, the new
  layers and any per-map exception; toggle survives a reload; with Terrain
  off the map is what it was before.

### FT-34 — The derived fact · High · deps: FT-33

- **Why:** 2 235 rows need something true to say, and no one is going to
  write 2 235 sentences. Everything needed is already in the sources.
- **Do:**
  - `data/scripts/build-facts.ts` reads the Natural Earth sources plus each
    `map.json` and writes `data/maps/<id>/facts.json`, one entry per target
    id, holding **structured fields, not sentences**:

    ```
    { "yunnan": { "type": "Autonomous region", "localName": "…",
                  "borders": ["Sichuan", "Guizhou", …], "coastal": false,
                  "terrain": ["Yunnan Plateau"], "largestCity": {…},
                  "position": "south-west" } }
    ```

  - the sentence is composed **at runtime** from i18n templates
    (`fact.region.borders`, `fact.city.capitalOf`, `fact.city.growth`…).
    That is what makes the derived half trilingual for free; proper nouns
    stay as they are, exactly as `i18n.svelte.ts` already says place names
    must;
  - per **city**: population and its rank on that map, national or regional
    capital, which region, coast or inland, growth since 1950, nearest
    named terrain;
  - per **region**: type and local name, who it borders, its biggest city,
    coastal or landlocked, which ranges or deserts cross it.
- **Reuse, do not rebuild:** adjacency is already computed by
  `data/scripts/mapColors.ts` for graph colouring — that is the `borders`
  list, for free. `overallBboxOf` gives "north-west of the country".
  `placeSelection.ts` already knows `ADM1NAME`.
- **Tests:** unit tests for the composer in all three languages; a second
  run of the script produces a byte-identical `facts.json` (MAPS.md's
  reproducibility rule); ten targets spot-checked against the source DBF.
- **DoD:** gates green; every map has a `facts.json`; `mapData.test.ts`
  checks each one against its `map.json`.

### FT-35 — The fact card · High · deps: FT-34

- **Do:** `app/src/lib/FactCard.svelte` plus `app/src/lib/facts.ts`
  (`fetchFacts(mapId)` and the pure composer), wired into four views:
  - **`OverviewView.svelte`** — tap a place, and hover too on a fine
    pointer. Every name is already written here, so nothing is given away;
  - **`MapView.svelte`** (Known) — on the click handler that already
    reveals the name;
  - **`QuizView.svelte`** — inside `markSolved`, so the card **cannot**
    appear before a name is resolved. A miss holds it until the next drop
    (that is the teaching moment); a clean answer shows it briefly. Never
    modal, never captures the pointer, never interrupts a drag;
  - **`TourView.svelte`** — fills `TourStep.narration`, declared in
    `tour.ts` and unused since iteration 6.
  - The card carries `data-map-overlay="bottom"` so `mapFit.ts` keeps the
    map clear of it, the contract the nav bar already uses at the top. In
    the quiz it sits above the tray.
  - `facts.json` is fetched **lazily**, not as part of the map load, so
    opening a map does not get slower; a missing file is not an error, the
    card simply does not appear.
- **Tests:** a browser test per view, including the negative one — no card
  before a quiz name is resolved — and that the map still fits with the
  card up.
- **DoD:** gates green; screenshots of all four views; 🧑 the product owner
  sees it before the merge.

### FT-36 — The authored hooks, pilot · Medium · deps: FT-35

- **Do:** `data/facts/italy.json`, `china.json`, `usa.json` — 103 hooks for
  Italy — Regions (20), China — Regions (33) and USA — Cities (50),
  projected into each map's `facts.json` by `build-facts.ts`.
- **Against the obvious failure mode — a confident, wrong sentence:**
  - a lint in `mapData.test.ts`: every hook resolves to a real target, no
    orphans, no duplicates;
  - each hook records the `wikidataid` it was written against, so it can be
    checked later;
  - 🧑 **all 103 go to the product owner as one readable list before the
    merge.** He is the only one who can say "that is not what Yunnan is
    known for". Offered as a private Artifact page for reading on any
    device — published only on his say-so.
- **DoD:** gates green; review done; DECISIONS.md records the voice the
  hooks are written in, so a later batch matches this one.

## Out of scope

- **The news line.** The product owner asked for it as a bonus — facts kept
  current, "somewhat related to geography". Fetching anything current needs
  the network, and the desktop and Android builds must work with none. The
  shape is reserved — an optional `news` field the card renders when
  present — but nothing fetches it in v0.8.0. It is its own task once the
  static half is proven.
- **Elevation shading** (decision 4). Deferred deliberately, not forgotten:
  it needs a DEM that is not Natural Earth, a new pipeline step, and it
  pushes every tileset up at the point where the native shells hold each one
  whole in memory.
- **Hooks for the other 60 maps.** Deliberately (decision 2): the voice gets
  judged on 103 before it is repeated 1 700 times.
- **Wikipedia or Wikidata text.** The ids are recorded, the text is not
  used. "Is a province of northern Italy" is exactly the sort of sentence
  that does not stick, and it carries a CC BY-SA attribution obligation
  that the rest of the data (public domain) does not.

## Risks

- **63 rebuilt tilesets is a 63-file binary diff.** Legitimate — the tiles
  genuinely change — but it is the largest single data change the project
  has made, and a map that breaks will break silently. The size table and
  the byte-identical `map.json` check are what stand between that and a bad
  release.
- **Download size again.** The APK is 29.7 MB. Four new layers across 63
  maps could plausibly add 3-6 MB. The gate in FT-33 caps the damage
  per map, but the total is worth measuring at the beta rather than at the
  store listing.
- **A wrong fact is worse than no fact.** The whole point is that these
  sentences stick — which means a wrong one sticks too. Hence the derived
  half being computed rather than written, the hooks being reviewed by a
  human before they ship, and the Wikidata id being recorded against each
  one.
- **The card can get in the way.** It appears in the quiz, which is a
  drag-and-drop game on a phone screen. If it crowds the tray or eats a
  drop, it is worse than nothing — which is why it declares itself to
  `mapFit` and why the quiz test includes a drag that must still land.
